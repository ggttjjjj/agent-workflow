# Workflow 规划阶段节点实施说明

日期：2026-11-16  
状态：已实施；本地自动化验证与真实浏览器/API 验收分开记录，后者尚未完成。  
关联：[通用 Agent 工作流 MVP 实施说明](agent-workflow-mvp.md)（§2 用户流程、§3 规划契约、§5 输入与上下文、§6 生成恢复、§7 审查编辑、§10 持久化、§13 验收、§16 缺口修复与剩余验收）。本文记录当前实现行为，不宣称真实联调已通过。

## 1. 目标与范围

已把实际运行的“需求分析”和“AI 编排”作为画布中的一等阶段节点，用户提交后即可感知进展，并在相应详情中查看可公开结果、处理澄清与编排异议。普通任务仍是尚未执行的任务定义，Agent 仍为定义数据，绝不暗示下游已执行。

本次已实施范围为以下可观察产品行为与交互，具体代码和验证入口见第 7 节。不增加下游执行、任意流程编排、模型选择、新工具能力或单阶段主动重生成。未另行说明的回答、取消、重试、候选审查、过期校验与保存恢复规则沿用 MVP。

## 2. 画布与编辑规则

1. 用户提交需求后立即显示“需求分析”和“AI 编排”两个节点，不等待完整方案生成。
2. 固定系统链路为 **需求分析 → AI 编排 → 所有无前置依赖的任务**。多个入口任务均连接 AI 编排；任务间依赖保持业务含义，系统连线不计作任务业务依赖或任务执行证据。
3. 阶段节点可以拖动，位置保存并在重开后恢复；不能删除、复制或改接系统连线。删除键、快捷键、双击、上下文菜单、拖线及批量操作均不能绕过保护；撤销重做不能破坏系统链路。
4. 普通任务继续支持编辑、增删、依赖修改与撤销重做；入口集合随业务依赖变化正确更新。布局整理仍可用，且保持阶段顺序、完整链路和普通任务连接，不丢失已保存布局。
5. 阶段节点采用与普通任务可区分的形状、颜色或标识，并以文案明确“实际运行的规划阶段”与“尚未执行的任务定义”，不可仅依赖颜色区分。
6. 移除左侧“方案生成进度”，把阶段进度放在画布节点中；耗时、用量、整体生成状态置于画布附近的概览区，未知用量不伪装成零。
7. 首次生成只有完整方案通过校验且保存成功后，才显示可编辑任务及 Agent；不显示未完成编排的任务预览。阶段公开输出预览可见，但必须标记“未校验”，不能误认为已保存结果。

## 3. 选择、详情与处理入口

- 点击阶段节点，右侧展示该阶段状态、配置、结果摘要和结构化结果；点击普通任务切回既有任务详情。
- 需求分析详情展示目标、受众、交付物、约束、排除项、假设、验收条件和澄清问答；保留影响当前需求的原始问答上下文。
- AI 编排详情展示 Agent 定义、任务分配、分工理由和编排异议。尚无本轮结果时明确显示“暂无本轮结果”，不能用旧结果冒充。
- 澄清回答、异议处理、取消、失败重试及仅重试保存入口归属相应阶段详情；不新增单阶段主动重生成。保存失败在整体概览和相关详情中独立提示。
- 只展示可公开结果，不展示模型内部思考内容。生成中公开结果预览始终带“未校验”标识。

## 4. 当前方案配置与请求快照

1. 两个阶段分别开放提示词、思考强度；只影响当前方案，不修改全局默认或其他方案。
2. 新方案继承创建时的全局默认；已有方案保留其原生成配置。保存节点配置仅供下一次用户主动重生成，不追溯修改历史修订或已生成结果。
3. 本轮生成开始即冻结请求配置；进行中、等待澄清、等待异议处理均锁定编辑。本轮完成、失败、取消或中断后解除锁定；保存失败仍须保留原请求快照及有效结果，不影响仅保存重试。
4. 回答及重试始终沿用原请求快照，不吸收后来修改的节点配置或全局默认。刷新后保留已保存的当前方案配置与历史配置，两者语义明确。

## 5. 状态、保存与版本

| 节点状态 | 含义与约束 |
|---|---|
| 未开始 | 尚未调用该阶段；上游等待、失败、取消或中断时，下游不得冒充已开始或已完成 |
| 进行中 | 当前阶段真实调用中，而非下游任务执行中 |
| 等待处理 | 澄清归需求分析；编排异议归 AI 编排，明确待办入口 |
| 已完成 | 该阶段本轮结果已通过相应校验；不代表整体已保存或下游已执行 |
| 失败 | 当前模型阶段调用或校验失败，与保存失败分开表达 |
| 已取消 | 本轮被用户取消；不接受迟到输出 |
| 已中断 | 服务或连接恢复后识别的中断，不自动重新调用模型 |

- 保存失败独立表达：已校验的模型阶段不得被伪装成失败，整体也不得显示成功；用户重试只保存，不重复调用模型。
- 编排失败重试复用有效需求分析结果；需求分析失败重试重新分析。旧需求对应的回答或重试继续受现有过期校验限制。
- 重生成期间保留原任务图，明确标记“当前已保存方案”；阶段节点展示本轮状态。旧结果若供参考，必须明确标记来源修订和历史属性。
- 新结果沿用候选比较与审查，只有用户采用后才替换原任务图。失败、取消、保存失败、放弃候选都不覆盖原方案。比较须展示需求原文版本以及需求、验收条件、任务、依赖、Agent 和分配的增删改。
- 状态更新不重置用户拖动位置、缩放和当前选择；只有用户主动选择或必要的对象不存在时才合理切换详情。重新打开恢复布局及可恢复状态，不自动调用模型。
- 历史方案、候选采用和放弃后均正确呈现系统阶段链路；历史结果不冒充本轮结果，历史方案配置不可被当前编辑追溯修改。

## 6. 验收场景与人工验收基线

| 编号 | 操作或故障 | 预期结果 |
|---|---|---|
| A01 | 首次提交文本、图片或混合需求 | 立即出现两个阶段节点；依次分析、编排；完成校验并保存前无可编辑任务或 Agent |
| A02 | PM 返回澄清并回答 | 分析显示等待处理，编排未开始；详情保留问答；回答沿用本轮快照继续 |
| A03 | 编排器提出异议并处理 | 异议归属编排详情；按既有流程重新分析衔接编排，配置持续锁定，状态不混淆旧结果 |
| A04 | 正常生成并保存 | 两阶段完成，整体已保存；展示完整任务、Agent 与覆盖，所有入口任务均连接 AI 编排 |
| A05 | 分别注入需求分析、编排失败并重试 | 失败阶段明确，下游不提前完成；编排重试复用有效 PM 结果，请求配置不变 |
| A06 | 在两阶段分别取消、中断、重试并重开 | 不接受迟到输出，不自动重新调用；恢复状态、布局和快照；明确重试入口 |
| A07 | 完整校验结果首次保存或后续保存失败 | 显示独立保存失败，不显示整体成功或模型失败；仅重试保存，模型调用次数不增加 |
| A08 | 修改需求后重试旧请求或回答旧问题 | 过期校验阻止旧结果生效；原已保存方案不被覆盖 |
| A09 | 修改并保存阶段配置、刷新、查看历史并主动重生成 | 当前方案下一次主动重生成使用新配置；其他方案、全局默认及历史生成配置不变 |
| A10 | 生成、等待澄清、等待异议期间尝试修改配置 | 均不可编辑；本轮结束解锁；重试不吸收后来配置修改 |
| A11 | 键盘删除、双击、复制、拖线、批量删除、撤销重做 | 阶段及系统连线均不可破坏；普通任务增删、依赖编辑、撤销重做仍正常 |
| A12 | 添加多个入口任务、改变依赖及布局整理 | 所有且仅入口任务连接 AI 编排；阶段链路、业务连接与布局正确 |
| A13 | 重生成、采用/放弃候选、失败或取消、重开历史 | 原图始终标识已保存方案；差异清晰；仅采用替换任务图；历史/本轮结果与配置不混淆 |
| A14 | 生成中查看预览并拖动、缩放、选择节点 | 仅可公开阶段输出带“未校验”；无内部思考或未编排任务预览；状态刷新不重置交互状态 |

验收需覆盖服务重启与浏览器刷新、首次与重生成两种路径；自动化测试不能代替真实 DeepSeek 文本/图片两阶段联调与浏览器完整验收（MVP §13.2）。

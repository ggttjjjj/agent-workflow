# 历史方案管理与删除

状态：已实现  
日期：2026-11-16

## 1. 目标与范围

左侧「我的方案」作为历史方案入口，支持查询、重命名、创建副本和删除；删除分「回收站」与「彻底删除」两级，重点保证：

- 删除可撤销，误删不会立即丢失数据；
- 彻底删除不可恢复，必须经过明确、可核对的二次确认；
- 删除正在生成的方案时，先取消生成，迟到的模型结果不会落库；
- 删除当前打开的方案时，界面、事件流和本地草稿同步清理；
- 其他窗口或标签页的删除不会让当前页面继续编辑一份已删除的数据。

本功能不改变需求分析、两阶段生成、候选稿、保存与确认的业务语义。

## 2. 数据与状态

- `Workflow.trashedAt`（ISO 时间）标记方案位于回收站；数据库仍使用原有 `documents` 表保存整份 JSON，不新增表，旧数据无需迁移。
- 普通读取、列表、SSE、生成、保存、确认、布局、重命名均看不到回收站方案（按 404 处理）；只有恢复、彻底删除和清空回收站会读取回收站数据。
- 回收站方案不可修改，版本号保持稳定，因此「撤销 / 恢复」可以使用版本号做并发校验。
- 每次业务修改仍使 `version` 加一；列表返回的摘要包含版本号、修订数、需求版本、任务数、Agent 数、图片数、候选标记和生成中标记。

## 3. 交互规则

### 查询

- 搜索同时匹配方案名称与需求文本摘要（摘要截取 80 字，大小写不敏感）。
- 方案项显示已确认 / 待审查、最新修订号、更新时间；生成中显示标记。
- 「方案 / 回收站」两个视图分别显示数量。

### 重命名

- 名称长度为 1–60 个 Unicode 码点，提交前去除首尾空白并合并连续空白。
- 不改变需求、方案内容、修订与确认记录；不要求版本号，生成中的方案也可以改名。

### 创建副本

- 生成新的方案 ID，名称追加「（副本）」并截断到 60 个码点。
- 保留需求与需求版本、全部保存修订、当前修订、画布布局。
- 有意丢弃生成任务与候选稿，避免副本显示为「生成中」或携带未采用的候选；同时清除副本修订的确认时间——确认针对具体方案记录，副本需要重新审查确认。
- 原方案与副本互不影响。

### 移入回收站

确认弹窗展示方案名称、确认状态、修订数、需求版本、任务 / Agent / 图片数量、生成状态和本地草稿状态。确认后：

1. 服务端在同一个事务中把正在进行的生成标记为「已取消」并写入 `trashedAt`；
2. 事务提交后中止在途模型请求；
3. 迟到的模型结果在写入时因方案已不可读而失败，不会产生新修订；
4. 浏览器清除该方案的本地编辑草稿；
5. 若删除的是当前打开的方案，关闭编辑区和需求弹窗；
6. 显示 10 秒可撤销提示，撤销时用回收站中的版本号恢复。

「移入回收站」不要求版本号：生成期间版本号每几百毫秒变化，若强制精确匹配会让删除几乎总是失败；删除的确认依据是弹窗中展示的方案信息，且操作本身可恢复。

### 恢复

- 仅回收站方案可恢复；恢复后回到「我的方案」，版本号加一。
- 恢复携带版本号做并发校验，版本不一致时提示刷新，不执行修改。

### 彻底删除（不可恢复）

- 只有已在回收站的方案才能彻底删除，避免绕过回收站直接销毁数据。
- 必须输入完整方案标题，输入框去空白后与内存中的标题精确比较；服务端再次与数据库中的标题比较，不一致返回 400，不删除任何数据。
- 成功后方案 JSON（含需求图片、修订、确认记录、布局）从 `documents` 表移除，之后即使带恢复参数也读取不到。

### 清空回收站

- 需要输入确认口令「清空回收站」。
- 请求同时携带客户端确认时看到的方案数量，服务端比对当前数量；数量不一致说明回收站已被其他窗口改动，返回 409 且不删除任何方案。

### 跨窗口删除

- 已打开方案被其他窗口移入回收站后，SSE 断开会触发一次列表查询；方案不在列表中时关闭当前编辑区并提示「该方案已被删除或移入回收站」。
- 方案管理中任何失败都会刷新列表，弹窗保留并展示错误，便于用户看清当前状态后重试。

## 4. 接口

| 方法与路径 | 说明 |
|---|---|
| `GET /api/workflows` | 返回 `{ plans, trash }` 两组方案摘要 |
| `PATCH /api/workflows/:id` | 重命名，body `{ title }` |
| `POST /api/workflows/:id/duplicate` | 创建副本，返回列表与副本 `id` |
| `POST /api/workflows/:id/trash` | 移入回收站（同时取消生成） |
| `POST /api/workflows/:id/restore` | 恢复，body `{ expectedVersion }` |
| `DELETE /api/workflows/:id` | 彻底删除，body `{ title }`（必须与标题一致） |
| `DELETE /api/workflows/trash` | 清空回收站，body `{ confirm, expectedCount }` |

## 5. 验证

- `tests/plans.test.ts` 覆盖：标题规范化与长度边界、副本标题与独立性、摘要字段、移入回收站后的读取 / 列表 / 修改隔离、恢复、过期版本、彻底删除前置条件、清空回收站数量校验、副本丢弃生成态、生成中删除后迟到结果不落库。
- 使用独立内存数据库对 HTTP 接口做了完整走查：创建 → 重命名 → 副本 → 移入回收站（读取与生成均 404）→ 恢复（含过期版本 409）→ 再次移入 → 错误标题 400 → 彻底删除 → 清空回收站（口令 400、数量 409、成功清空）。
- 使用无头 Edge 在桌面与 390×844 移动视口走查：管理菜单、删除确认、撤销、回收站恢复、彻底删除确认和移动端弹窗；无控制台异常、无横向溢出。

## 6. 边界

- 不做批量勾选删除、回收站自动过期、跨设备同步或导出；本地单用户场景下以确认和可撤销为主。
- 彻底删除后 SQLite 的 WAL 可能短期保留已删除页；本地应用不做磁盘级安全擦除。
